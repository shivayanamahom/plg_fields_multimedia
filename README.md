Плагин пользовательского поля Joomla 5/6 для **галереи изображений** и **списка файлов**. Загрузка с компьютера или выбор из менеджера медиа, миниатюры, слайдер, просмотр через [WT Fancybox](https://web-tolk.ru/en/dev/wt-fancybox) и макеты, которые можно переопределить в шаблоне.

> **Для разработчиков и ИИ-агентов:** перед правками прочитайте [AGENTS.md](AGENTS.md) — там архитектура, правила безопасности и порядок сборки.

## Что умеет

- **Два режима поля — «Галерея» и «Файлы».** Режим выбирается при создании поля и **после сохранения не меняется**; в настройках остаются только параметры своего режима.
- **Нативный интерфейс Joomla:** поле строится на стандартном повторяемом subform — в каждой строке штатное поле «Медиа» (выбор файла, предпросмотр), описание (оно же alt и подпись), порядок меняется перетаскиванием.
- **AJAX-загрузка с компьютера** (кнопка или перетаскивание файлов на поле) с обработкой на сервере: каждый файл превращается в новую строку списка.
- **Обработка изображений при загрузке:** вписать в рамку или обрезать по рамке, качество, преобразование в WebP, поворот по EXIF. Метаданные (EXIF, геометки) удаляются.
- **Миниатюры** создаются при первом показе и кэшируются.
- **Вывод на сайте:** сетка или слайдер (CSS scroll-snap, без библиотек), список или карточки для файлов.
- **Просмотр крупно:** через плагин **WT Fancybox**, если он установлен и включён, иначе — встроенное окно на `<dialog>`. Внешние сети (CDN) не подключаются.
- **Переопределяемые макеты:** вся разметка (поле в админке, галерея, файлы, окно просмотра) лежит в `layouts/` и заменяется из шаблона.
- **Безопасность:** настройки загрузки берутся на сервере, а не от браузера; проверка содержимого файлов, защита папки загрузок, фильтр значения при сохранении (см. [раздел ниже](#безопасность)).

## Установка

### Вариант 1: по URL (без скачивания архива)

```text
https://github.com/shivayanamahom/plg_fields_multimedia/releases/latest/download/plg_fields_multimedia.zip
```

1. **Система → Установка → Расширения → «Установить по URL-адресу»**.
2. Вставьте ссылку и нажмите **«Проверить и установить»**.

### Вариант 2: архив из Releases

Скачайте `plg_fields_multimedia-<версия>.zip` со страницы [Releases](https://github.com/shivayanamahom/plg_fields_multimedia/releases) и загрузите во вкладке **«Загрузить файл пакета»**.

После установки плагин включается сам. Обновления приходят через стандартный механизм Joomla (сервер обновлений — `updates.xml` в этом репозитории).

## Как пользоваться

1. **Содержимое → Поля → Создать** (или «Пользовательские поля» нужного раздела).
2. Тип поля — **«Мультимедиа (галерея или файлы)»**.
3. Вкладка **«Параметры»**: выберите **режим** и задайте настройки.
4. Сохраните поле. Режим закрепится, а настройки другого режима исчезнут из формы.
5. В материале появится список строк: файл выбирается штатной кнопкой «Выбрать» (менеджер медиа Joomla), порядок меняется перетаскиванием, строки добавляются и удаляются кнопками ядра. Кнопка **«Загрузить с компьютера»** (и перетаскивание файлов на поле) загружает файлы AJAX-ом и сама добавляет строки.

Выбор из менеджера медиа ограничен настройками «Медиа» Joomla (допустимые расширения изображений и документов); дополнительно плагин при сохранении оставляет только расширения из настроек поля.

Нужна и галерея, и документы — создайте два поля.

### Общие настройки

| Параметр | Описание |
|---|---|
| Папка загрузки | Подпапка в `images/`: латиница, цифры, `-`, `_`, до четырёх уровней. По умолчанию `multimedia` |
| Подпапки | Без подпапок / по году и месяцу / по имени поля |
| Максимум элементов | 1–200. Для одного изображения или документа укажите 1 |
| Максимальный размер файла, МБ | Не больше `upload_max_filesize` и `post_max_size` PHP; проверяется и на сервере |
| Удалять файлы вместе с записью | Выключено по умолчанию; см. [удаление файлов](#удаление-файлов) |

### Режим «Галерея»

| Параметр | Описание |
|---|---|
| Изменение размера | Не менять / вписать в рамку / обрезать по рамке. Мелкие изображения не увеличиваются |
| Ширина и высота рамки | 100–6000 px |
| Качество | 40–100 %, для JPEG и WebP |
| Преобразовывать в WebP | Для загруженных JPEG/PNG. Анимированные GIF не меняются |
| Вид галереи | Сетка или слайдер |
| Колонок | 1–6 на широком экране; на планшете не больше двух, на телефоне одна |
| Миниатюра: ширина × высота | Обрезка по центру; ширина `0` — выводить оригиналы |
| Описание под фото | Показывать описание под изображениями; описание всегда используется как alt |
| Просмотр крупно | WT Fancybox (если подключён) или встроенное окно |
| Автопрокрутка | Секунды для слайдера; `0` — выключена; не работает при «уменьшить движение» |

### Режим «Файлы»

| Параметр | Описание |
|---|---|
| Допустимые расширения | Список через запятую, по умолчанию `pdf,doc,docx,xls,xlsx,ppt,pptx,odt,ods,txt,csv,zip` |
| Вид списка | Список или карточки |
| Показывать тип и размер | Например `PDF, 244 KB` |
| Действие по клику | Открыть в новой вкладке или скачать |

В режиме «Файлы» у каждого файла есть поле «Название для посетителей»; если оно пустое, показывается имя файла.

## Просмотр крупно и WT Fancybox

Плагин сам ничего не подгружает из интернета.

- Если установлен и **включён** системный плагин [WT Fancybox](https://web-tolk.ru/en/dev/wt-fancybox), галерея подключает его WebAsset-пресет `wtfancybox` (локальные файлы) и открывает изображения через Fancybox: группа на поле, подписи из поля «Описание».
- Если плагина нет или он выключен, используется встроенное окно просмотра (`<dialog>`): стрелки, `Esc`, клик по фону.
- Отключить просмотр можно в настройках поля («Просмотр крупно» — «Нет»).

## Переопределение макетов

Каждый макет можно заменить, не трогая плагин. Скопируйте файл из `layouts/plg_fields_multimedia/` в папку шаблона и меняйте:

```text
templates/<шаблон>/html/layouts/plg_fields_multimedia/gallery.php
```

| Файл | Что выводит |
|---|---|
| `field.php` | Обёртка поля в форме материала: кнопка загрузки, подсказка и штатный subform Joomla |
| `gallery.php` | Обёртка галереи: сетка или слайдер, навигация |
| `image.php` | Одно изображение: ссылка на просмотр, `<img>`, подпись |
| `lightbox.php` | Встроенное окно просмотра |
| `files.php` | Список или карточки файлов |
| `file.php` | Одна строка списка файлов |

Общий вывод значения (подготовка данных) можно заменить файлом `templates/<шаблон>/html/plg_fields_multimedia/multimedia.php` — копия [tmpl/multimedia.php](tmpl/multimedia.php).

Данные макета описаны в шапках файлов (`@var`). Хелперы `Joomla\Plugin\Fields\Multimedia\Helper\MediaHelper` (`url()`, `thumbnail()`, `formatSize()`) доступны в любом макете.

Цвета, отступы и пропорции галереи меняются CSS-переменными `--mm-*` на `.multimedia-field` (например, `--mm-gap`, `--mm-radius`, `--mm-ratio`, `--mm-nav-size`).

## Безопасность

Плагин переписан с упором на безопасность загрузки файлов.

**Загрузка**

- Настройки (папка, лимиты, расширения, режим) сервер берёт из параметров поля по `field_id`. Браузер присылает только файл и id поля — подменить параметры нельзя.
- Проверяются токен формы (CSRF), вход пользователя, уровень доступа к полю и права `core.edit.value` + создание/редактирование в компоненте.
- Тип определяется по **содержимому** (`finfo`), а не по расширению. Для изображений дополнительно `getimagesize()`: тип должен совпасть с расширением, размеры ограничены (12000 px, 64 Мпикс).
- Изображения **пересохраняются через GD**: в результате нет EXIF/GPS и «хвостов» с кодом после данных картинки (проверено на jpeg с вшитым `<?php`).
- Расширения исполняемых и активных типов (`php`, `phtml`, `phar`, `html`, `svg`, `js`, `exe` и др.) отклоняются всегда, даже если указаны в настройках; двойные расширения (`shell.php.jpg`) тоже.
- Файлы режима «Файлы» не должны содержать `<?php`; MIME должен соответствовать расширению (для известных форматов).
- Имя файла — латиница из исходного имени (кириллица транслитерируется); при совпадении добавляется суффикс, перезапись исключена (файл создаётся режимом `x`).
- Папка загрузок — только внутри `images/`, путь проверяется через `realpath` (защита от symlink); создаётся `.htaccess` и `web.config`, запрещающие выполнение скриптов.

**Сохранение значения**

- Значение проходит серверный фильтр: остаются только существующие файлы внутри `images/` с разрешёнными расширениями, без дублей, не больше лимита; подписи очищаются от тегов.
- Режим уже сохранённого поля принудительно берётся из базы — подменить его запросом нельзя.

**Вывод**

- Всё экранируется; в разметке нет inline-скриптов и стилей, поэтому подходит строгая политика CSP.
- Отсутствующие на диске файлы на страницу не попадают.

### Удаление файлов

Опция «Удалять файлы вместе с записью» по умолчанию выключена. Если включить, при удалении материала плагин удалит его файлы, но **только**:

- из папки загрузки этого поля (`images/<папка>`), не по произвольному пути из значения;
- с расширением, разрешённым в настройках поля;
- если на файл не ссылается значение другого поля или записи;
- не по символической ссылке.

Файлы, которые убрали из списка вручную, остаются на сервере (в менеджере медиа их можно удалить обычным способом).

Очистка работает для записей, у которых контекст поля совпадает с контекстом удаляемого объекта (`com_content.article` и подобные).

## Обновление с версии 1.x

Версия 2 — переработка: другие параметры и структура. Данные не теряются:

- Старые значения (JSON-список `file/type/alt` и одиночный путь) читаются как есть.
- Поля, созданные в 1.x, **не имеют закреплённого режима**. Откройте каждое поле, выберите режим, проверьте настройки и сохраните — после этого режим закрепится.
- Если в старом поле лежали и изображения, и документы — разделите их на два поля.
- Стили и скрипты теперь в `media/plg_fields_multimedia/`, старый набор в `plugins/fields/multimedia/media/` удаляется при обновлении.
- Переопределения макетов из `html/layouts/plg_fields_multimedia/` нужно сверить с новыми файлами (`gallery`, `image`, `files`, `file`, `lightbox`, `field`).

## Структура

```text
plg_fields_multimedia/
├── multimedia.xml                      манифест
├── services/provider.php               DI
├── src/
│   ├── Extension/Multimedia.php        плагин: события, AJAX-загрузка, блокировка режима, очистка
│   ├── Field/MultimediaField.php       поле ввода (админка и форма на сайте)

│   └── Helper/                         MediaHelper, UploadHandler, ImageProcessor, UploadException
├── params/multimedia.xml               параметры поля (режимы)
├── tmpl/multimedia.php                 вывод значения на сайте
├── layouts/plg_fields_multimedia/      переопределяемые макеты
├── media/                              CSS/JS и joomla.asset.json
├── language/                           ru-RU, en-GB
└── tests/run.php                       проверки безопасности и обработки файлов
```

## Разработка

```bash
tools/build.sh                          # dist/plg_fields_multimedia-<версия>.zip
JOOMLA_ROOT=/path/to/site php tests/run.php   # тесты на живой установке Joomla
```

Тесты создают и удаляют временную папку `images/zz-mmtest` в указанной установке и не меняют базу данных.

Релиз: поднимите `<version>` в `multimedia.xml` и отправьте изменения в `main` — GitHub Actions соберёт архив, создаст релиз и обновит `updates.xml`.
